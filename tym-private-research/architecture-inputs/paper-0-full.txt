2.  Definitions  
The  following  definitions  clarify  the  central  concepts  used  throughout  this  paper.  
2.1  Events  The  notion  of  an  event  is  close  to  that  used  in  TimeML  [1].  In  narrative  text,  events  are  
commonly
 
realised
 
by
 
verbs
 
or
 
deverbal

Syntactically,
 
an
 
event
 
usually
 
appears
 
at
 
the
 
clause
 
level,
 
around
 
a
 
main
 
verb
 
or
 
a
 
verbal

Semantically,

event
 
expresses
 
an
 
action,

or

which
 
participants

roles
 
such
 
as
 
agent,

experiencer,
 
or

These

are
 
typically
 
realised
 
as
 
subjects,
 
direct
 
objects,
 
indirect
 
objects,
 
or
 
oblique
 
complements.
 Events  are  positioned  on  the  story  time  axis  either  by  explicit  temporal  expressions,  such  as  a  
year,
 
month,
 
day,
 
holiday,
 
or
 
moment,
 
or
 
by
 
relations
 
to
 
other
 
events.
 
Two
 
events
 
may
 
be
 
simultaneous,
 
partially
 
overlapping,
 
before
 
one
 
another,
 
or
 
after
 
one
 
another
 
[2].
 
In
 
many
 
literary
 
passages,
 
however,
 
an
 
event
 
is
 
not
 
anchored
 
by
 
a
 
concrete
 
date
 
or
 
time.
 
The
 
semantic

of
 
a

is

only
 
partially
 
ordered
 
along
 
the
 
story
 
time
 
axis.
 Entities  participate  in  events.  These  entities  may  be  book  characters,  objects,  places,  
organisations,
 
or
 
abstract
 
ideas.
 
In
 
TYM,
 
persons
 
are
 
especially
 
important
 
because
 
time
 
tracks
 
often
 
centre
 
on
 
characters
 
and
 
their
 
roles
 
in
 
events.
 
This
 
study
 
focuses
 
primarily
 
on
 
agents
 
and
 
recipients,
 
corresponding
 
to
 
syntactic
 
positions
 
such
 
as
 
subjects,
 
direct
 
objects,
 
and
 
indirect
 
objects
 
associated
 
with
 
the
 
main
 
verb.

TYM

 Unity  of  time  means  the  events  within  a  TS  are  synchronous,  contiguous,  or  sequentially  
coherent
 
on
 
the
 
story
 
time
 
axis.
 
The

of
 
characters
 
means
 
that
 
the
 
main
 
participants
 
remain

stable  throughout  the  segment.  The  unity  of  perspective  means  that  the  events  are  narrated  
from
 
the

whether
 
that

of
 
view
 
belongs
 
to
 
the
 
authorial

2.3  Time  Tracks  (TTs)  A  Time  Track  (TT)  is  a  maximal  sequence  of  time  segments  that  are  partially  ordered  with  
respect
 
to
 
the
 
story
 
time

involve

narrated

The

to
 
the

span:

a
 
chosen

of
 
characters

Because

character
 
set

 The  notion  of  a  time  track  is  related  to  the  notion  of  a  narrative  thread.  By  following  one  
character,

can

intersects
 
with
 
other
 
characters,

and

A

of
 
TSs
 
may

story

in

point
 
where
 
they
 
are
 
mentioned

A

A

3.  Processing  Pipeline  
The  logical  sequence  for  implementing  TYM  is  as  follows:  1.
   
 
Identify  events  by  detecting  clause  boundaries  and  extracting  the  main  verbal  
predicates.
 2.
       
Identify  temporal  relations  between  events  and  between  events  and  explicit  temporal  
anchors.
 3.
       
Identify  the  characters  and  other  named  entities  that  participate  in  each  event.  4.
       
Identify  the  narrative  perspective  from  which  each  event  is  told.  5.
       
Detect  time-segment  boundaries  as  continuous  spans  in  which  temporal  flow,  character  
set,
 
and
 
perspective
 
remain
 
stable.
 6.
       
Build  time  tracks  for  a  user-selected  set  of  characters  by  selecting  the  relevant  TSs  and  
ordering
 
them
 
on
 
the
 
story
 
time
 
axis.
 7.
       
Validate  the  implementation  with  reproducible  tests,  schema  checks,  and  evaluation  
scripts,
 
preferably
 
maintained
 
in
 
an
 
agentic
 
workflow
 
such
 
as
 
Codex.

3.1  Event  Segmentation  Events  are  the  basic  units  from  which  time  segments  are  built.  In  the  original  implementation,

Chunking

identified

multiple
 
verbs,

or
 
punctuation

 The  modernised  pipeline  keeps  these  rules  as  transparent  baselines  but  adds  dependency  
parsing

A

 A  simplified  version  of  the  updated  algorithm  is  shown  below:  
1:  sentences  =  SentenceSplit(document)  2:  for  each  sentence  in  sentences:  3:      tokens,  pos,  dependencies  =  LinguisticPreprocess(sentence)  4:      candidates  =  SplitByVerbConjunctionsPunctuation(tokens,  pos,  dependencies)  5:      events  =  Enrich(candidates,  tense,  aspect,  actors,  time_expressions,

InferAnchorFromPreviousEventOrDiscourseContext(events)
 8:      label  =  ClassifyTemporalType(event,  model,  rules)  9:      store  event  with  provenance  for  each  inferred  attribute  
The  provenance  requirement  is  important:  every  inferred  actor,  temporal  anchor,  or  relation

explicit
 
text

3.6  Detecting  Time  Tracks  Given  a  text,  the  system  should  identify  and  represent  time  tracks  together  with  their  associated  
units.
 
The
 
following
 
notation
 
is

 ·
         
C  =  {c0,  c1,  ...,  cn}:  the  set  of  characters.  ·
         
T  =  {t0,  t1,  ...,  tn}:  the  set  of  temporal  anchors.  ·
         
P  =  {p0,  p1,  ...,  pn}:  the  set  of  perspectives.  In  the  baseline,  P  =  {author}.  ·
         
EV  =  {ev0,  ev1,  ...,  evn}:  the  set  of  events.  Each  event  includes  actors,  a  temporal  
anchor,
 
location,
 
action,
 
tense/aspect,
 
order
 
number,
 
and
 
provenance

 ·
         
TST  =  {Past,  Present,  Future}:  the  temporal  categories  used  in  the  baseline  classifier.  ·
         
TS  =  {ts0,  ts1,  ...,  tsn}:  the  set  of  time  segments,  where  each  segment  contains  an  
ordered
 
list
 
of
 
events.
 ·
         
TT  =  {tt0,  tt1,  ...,  ttn}:  the  set  of  time  tracks,  where  each  track  contains  ordered  pairs  of  
time
 
segments
 
and
 
temporal

set
